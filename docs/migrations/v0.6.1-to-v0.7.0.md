# Migrating from `v0.6.1` to `v0.7.0`

Update the `sdlc` binary and the plugin together, as
[Updating](../installation.md#updating) says: an old binary beside the new plugin does not know
the new commands and flags, and answers `SDLC-E0034` for them. Do the configuration edits below
on trunk, between stories, because a story cannot carry a change to `.sdlc/`.

## `fix(hook)!: run a person's typed slash command in Claude Desktop's Code tab` (`77283f2`)

Commit `77283f22d4c3bf90df8fe6ae50c7a8799acf3142`.

### What changed

Claude Code 2.1.312 and later sets `AI_AGENT` in every hook it runs, so the hook read a person's
`/sdlc:approve`, `/sdlc:unfreeze`, `/sdlc:ack`, `/sdlc:remap`, `/sdlc:release` and `/sdlc:assign`
typed in Claude Desktop's Code tab as a model's and refused it. The hook now runs a typed command
only where four parts of its own environment say that Claude Code started it for a session a
person attends: `AI_AGENT` holds the label Claude Code gives a hook it runs itself
(`claude-code_`, a version, `_harness`), `CLAUDE_CODE_EXECPATH` is not set, `GIT_EDITOR` is not
`true`, and `CLAUDE_CODE_SESSION_ATTENDED` is `1`. A part that is absent or different refuses.

The refusal reads differently: it says the command did not run, names each variable that failed
and never its value, and gives a `!` line in Claude Desktop or a terminal outside Claude Code as
the way round. [`enforcement-stays-on`](../enforcement.md#enforcement-stays-on) now protects six
names where it protected one: `AI_AGENT`, `CLAUDE_CODE_EXECPATH`, `GIT_EDITOR`,
`CLAUDE_CODE_SESSION_ATTENDED`, `CLAUDE_CODE_CHILD_SESSION` and `CLAUDE_CODE_ENTRYPOINT`. The shell
rules refuse a model that removes, blanks or sets any of them, because changed by a model they
could make its own payload pass for a person's command.
[`story-stays-in-its-session`](../enforcement.md#story-stays-in-its-session) reads more nested
starts of a session (`osascript` handing Terminal or iTerm a command, `socat` `EXEC`, `SYSTEM` and
`SHELL` addresses, `python -m pty`, a shell fed its input under a pty, and `claude` named by a
Windows path or the native installer's versioned binary), and refuses a spelling it cannot read.

### Steps

1. Nothing to change in the configuration or the backlog.
2. If you set `AI_AGENT`, `CLAUDE_CODE_EXECPATH` or `GIT_EDITOR=true` in the shell you start
   Claude Code from, or in Claude Desktop's local environment editor, take it out and open a new
   session. With any of them set there, a slash command answers that it did not run.
3. If a script matches the old refusal text of a slash command, match the variable names instead.
4. A Claude Code older than 2.1.321 may give its hooks another label or no
   `CLAUDE_CODE_SESSION_ATTENDED`, and then the hook says to update it. Claude Code 2.1.321 in
   Claude Desktop is the release the four variables were read in.

### Verify

In a session you opened yourself in Claude Desktop, type a command the loop leaves to a person,
for example `/sdlc:ack` on a project with something to acknowledge. Where the hook cannot tell
that you typed it, it answers:

```text
/sdlc:ack did not run: the hook could not tell that a person typed it: ...
```

followed by one reason for each variable that failed, and the `!` line to type instead. Where it
can, the command runs and prints what the `sdlc` command prints. A model that tries to unset or
set one of the six names in a shell command is refused by `enforcement-stays-on`.

## `feat(cli)!: pause before commit for the paths a change touches, not only its tier` (`f4ce512`)

Commit `f4ce512aab8c53d5927d8cf53815a9e5527dba51`.

### What changed

A high tier paused every story however little it touched, and a low one never paused, even for a
change to what separates a person from a model. `human_gates.pre_commit_pause_paths` is a new
list of globs from the repository root. The commit gate, the hook and the landing now pause for a
person's approval where a changed, moved, deleted or untracked file matches one, or where the
story's tier is in `pre_commit_pause_tiers`, as before. In a story's worktree the main
checkout's lists and the worktree's own copy count together, and in one checkout the file at the
story's base counts too, so a story cannot narrow a pause by editing its own copy.

The texts of `SDLC-E0037` and `SDLC-E0075` name a path as well as the tier.
`sdlc status --json` gains `pre_commit_pause` until the commit gate passes, and `sdlc status`
prints a `pause` line. A story that passes the commit gate with no pause leaves a
`landed_without_pause` event, which `sdlc log` shows as a `no pause` line until `sdlc ack` marks
it read. That is so in every project, including one that never sets the key. `sdlc init` writes
`pre_commit_pause_paths` into a new config.

### Steps

1. Optional: add `pre_commit_pause_paths` to `human_gates` in `.sdlc/config.json`, beside the tiers
   you already have, and commit it on trunk. Without it the key is `[]` and only the tier pauses a
   story, as before. A new project from `sdlc init` gets this, which pauses high-tier stories and
   no path:

   ```json
   "human_gates": {
     "pre_commit_pause_tiers": ["high"],
     "pre_commit_pause_paths": [],
     "dor_advocate_check": false
   }
   ```

2. To pause a low-tier story that touches what decides who may approve, commit or enforce, list
   those paths. Each glob is slash-separated, from the repository root, and is matched without
   regard to case; a bare directory covers what is under it:

   ```json
   "human_gates": {
     "pre_commit_pause_tiers": ["high"],
     "pre_commit_pause_paths": ["src/auth/**", "install.sh"]
   }
   ```

3. Empty `pre_commit_pause_tiers` only once every machine that works the project runs a release
   that reads the paths: an older release ignores the key.
4. A glob that does not parse, starts with `/`, holds a backslash or `..`, or is not in its plainest
   form is refused when the file loads, with `SDLC-E0045` naming the entry.
5. If a script reads `sdlc status --json`, `sdlc log` or the text of `SDLC-E0037` or
   `SDLC-E0075`, allow the new key, the new event and the longer text.

### Verify

```console
$ sdlc doctor
$ sdlc status
```

`doctor` exits 0 and names no glob it refuses. On a story in flight, `status` has a `pause` line
under `next` saying whether the commit will wait for a person and why: the tier, and each file
with the glob it matched. After a story commits with no pause, `sdlc log` shows a `no pause` line
for it.

## `feat(team)!: wait for the test reviewer before an extending freeze, whatever a rename's case` (`5c974ae`)

Commit `5c974ae15034e20d7b3710b3764dcf878737abf0`. Commit `1082c8c` carries the rest of the
change.

### What changed

The plugin has a thirteenth agent, `test-reviewer`, which reads the new tests against the
criteria, `ANALYSIS.md`, `THREATS.md` and `TEST-PLAN.md` at Gate 3, runs them, and approves or
blocks. `sdlc freeze` now waits for its review of the test files as they are, by name and
content, and refuses until it has one: with `SDLC-E0029` where the review is missing, is not an
approve or is of tests that have changed since, and with `SDLC-E0030` where it blocked. This holds
wherever the agent is enabled, whether the project manager is off or a staffing has no row for
it. A test changed, added or renamed after the approve makes it stale. Where its `can_block` is
`false`, the freeze waits only until it has reviewed.

An extending freeze, under `freeze.allow_new_test_files`, now hashes the test names it lists
themselves, so a frozen test renamed only by case on macOS or Windows no longer enters the digest
with an empty hash that no approve could match. Both refusals now begin with a line of their own
saying that the freeze waits for the test reviewer's review of the tests as they are.

### Steps

1. Update the plugin with the binary: the new agent is in the plugin, and `sdlc freeze` waits for
   a review the old plugin cannot make.
2. To keep the freeze as it was, turn the agent off on trunk, between stories. It is on by
   default, so a `team.agents` section that does not name it leaves it on, and `sdlc init` writes
   it as enabled in a new config:

   ```json
   "team": {
     "agents": {
       "test-reviewer": { "enabled": false }
     }
   }
   ```

3. To keep the review but not let it stop the freeze, set `"can_block": false` on the same entry.
   The freeze then waits only until the reviewer has reviewed.
4. If a script matches the first lines of the `sdlc freeze` refusals `SDLC-E0029` and
   `SDLC-E0030`, allow the new first line.

### Verify

```console
$ sdlc staffing show
$ sdlc freeze
```

`staffing show` lists `test-reviewer` with the other enabled agents, or under disabled where you
turned it off. With it on and no approve recorded, `sdlc freeze` is refused with `SDLC-E0029` and
`why  test-reviewer has not reviewed`, and takes no freeze. With it off, the freeze waits for
nothing.

## `feat(cli)!: let the loop decide implementation questions and stop only on product ones` (`b0b7ae7`)

Commit `b0b7ae7f5f822b17b044d719b9fcca4bd3cb227c`.

### What changed

The loop used to hand a person every question an agent raised, including those that only choose
between two ways of meeting a criterion, and a reviewer that kept blocking stopped the story. Now
[two kinds of decision](../the-loop.md#two-kinds-of-decision) are told apart. A product decision,
one about what the user sees or can do, is still a person's: `sdlc escalate` takes the word
`product_decision`, which Gate 2 uses once per story with every product question in it. An
implementation decision is the loop's, and `sdlc decide <ID>` records it with `--question`,
`--option` (two to ten), `--chosen`, `--reason` and `--by`. It writes a `decision` event to the
gate record and the story's `DECISIONS.md`, which only the tool writes. A malformed call is
refused with `SDLC-E0094` and records nothing.

`sdlc log` lists decisions, `sdlc ack` covers them, `sdlc status` gains `decisions_unread` in
`--json` (always present, `0` included), and `sdlc trace --all` counts them per story. At a
reviewer's limit-th block, `loop.max_review_rounds` or its own `team.agents.<agent>.max_rounds`,
the gate goes to `<role>-arbiter`, a fresh instance one step up in `team.efforts` (or in
`team.models` where effort is at its ceiling). Its review stands for the role until a person
answers a `review_not_converging` hand-over raised at that gate. A block no longer hands the story
over while the arbiter has not ruled. `sdlc review add --json` gains `arbiter`. A role the
project disables has no arbiter, and its limit hands the story over as before. The scaffolded
contract also says the loop may add an open-source dependency whose licence the project's check
accepts, and records it with `sdlc decide`.

### Steps

1. Nothing to change in the configuration or the backlog.
2. If a script reads `sdlc status --json`, `sdlc log` or the JSON of `sdlc review add --json`,
   allow `decisions_unread`, the decision lines and `arbiter`. A script that treated a reviewer's
   limit-th block as the end of a story now sees the gate go to the arbiter.
3. Optional: in your own `## SDLC Contract`, under "Allowed dependencies", say whether the loop
   may add a licensed dependency and name the licence check, as a new project's contract now does.
   That file is yours to change on trunk; no command rewrites it.
4. Run `sdlc ack` as you did, to mark the decisions read once you have looked at them.

### Verify

```console
$ sdlc status --json
$ sdlc decide US-001 --question "Which file holds the parser?" --option "internal/parse" \
    --option "internal/cli" --chosen "internal/parse" --reason "it keeps the reader out of the CLI" \
    --by implementer
```

`status --json` has `decisions_unread`. On a story under way, `decide` prints one line naming the
story, the gate, `D-1`, who decided and `DECISIONS.md`. The same call with `--chosen` not among the
options exits 1 with `SDLC-E0094` and records nothing.

## `feat(cli)!: send the tests to the test reviewer's arbiter at its limit, and name the arbiter in the refusal` (`a5c1c71`)

Commit `a5c1c71e327fb038d682b9636907993117e3574d`.

### What changed

The test reviewer follows the arbiter rule of the commit before it. At its `max_rounds`
(`loop.max_review_rounds` where it has none), the `tests_frozen` gate goes to
`test-reviewer-arbiter`, and only the arbiter's own limit hands the story to a person. A gate that
has gone to its arbiter refuses with `SDLC-E0030` naming the arbiter, even after the work has
changed, instead of pointing at a reviewer that is itself refused. `sdlc freeze` reads the
arbiter's review in the test reviewer's place. `sdlc review list --json` gains `gone_to`, which
names the arbiter from the reviewer's limit-th block until the arbiter first reviews.

### Steps

1. Nothing to change in the configuration or the backlog.
2. If a script reads `sdlc review list --json` or the `SDLC-E0030` text of `sdlc freeze`, allow
   `gone_to` and the arbiter's name.
3. Update the plugin: the runbook delegates to `test-reviewer-arbiter` at that point.

### Verify

```console
$ sdlc review list
$ sdlc staffing show --gate tests_frozen
```

After the test reviewer has blocked as many times as its limit, `review list` says that
`tests_frozen` has gone to `test-reviewer-arbiter`, which reviews it next, and `sdlc freeze` is
refused with `SDLC-E0030` naming the arbiter. `staffing show --gate tests_frozen` lists the
arbiter in the reviewer's place.

## `feat(cli)!: run a tree's tests and checks once, at Gate 5, and reuse the result` (`eef7797`)

Commit `eef7797ed231787b03319f96f4ed39c490f8ac6f`.

### What changed

The suite ran up to four times per story, for the implementer, the verifier, the freeze and the
landing. `sdlc gate implementation pass` now runs the configured `build`, `test`, `lint`,
`fmt_check`, `coverage` and `mutation` that are set, in that order, in the story's worktree, and
records the result against the tree hash, a digest of each command and its threshold, and each
command's exit status and duration, never the command's text. The verifier cites a held result,
and the landing lands on it without running the commands again where it is for the tree and
commands as they are. `sdlc status --json` shows it in a `commands` block, with `current`.

Each run is handed one new directory, `SDLC_RUN_DIR`, outside the project, so that `test` can
leave its coverage data where `coverage` reads it. A command that fails, misses a threshold or
prints no figure refuses the gate with `SDLC-E0095` and counts as a fail of the gate towards
`loop.max_rework_rounds`; its output is in `.sdlc/stories/<ID>/implementation-run.log`. A command
that could not be started, wrote a file of the tree it ran on, or ran while the story changed
records nothing. The commit message calls this code `SDLC-E0094`; the catalogue gives `SDLC-E0094`
to a refused `sdlc decide`, and this refusal is `SDLC-E0095`.

The freeze now runs only the new tests, with `commands.test_files` and the list in
`SDLC_TEST_FILES`, and proves they fail. Where they pass, the freeze is refused with
`SDLC-E0085`, since tests that pass against the old code test nothing yet. A new shell rule,
[`commands-run-as-configured`](../enforcement.md#commands-run-as-configured), refuses a line that
sets, exports or otherwise changes the environment before `sdlc freeze` or
`sdlc gate implementation pass`, because the recorded result now stands in for a rerun and a
session must not choose what the commands run with. On PowerShell the call must stand alone.

### Steps

1. Set `commands.test_files` on trunk, between stories. A project without it is not refused: the
   freeze falls back to the whole `commands.test`, and runs nothing where neither is set. The
   key then makes the freeze run only the tests the story added. `sdlc init` writes it for Go,
   Rust, Node and Python and leaves it empty for another stack. For Go, it runs the packages that
   hold the files in `SDLC_TEST_FILES`, a file under `testdata/` standing for the package above it:

   ```json
   "commands": {
     "test_files": "if [ -n \"${SDLC_TEST_FILES-}\" ]; then sed -e 's#^#./#' -e 's#/testdata/.*#/x#' -e 's#/[^/]*$##' \"$SDLC_TEST_FILES\" | tr '\\n' '\\0' | xargs -0 go test -count=1; else go test ./... -count=1; fi"
   }
   ```

   [The narrow test command](../configuration.md#the-narrow-test-command) gives the Python, Rust
   and Node forms.
2. Optional: have `test` leave its coverage data in `SDLC_RUN_DIR` and `coverage` read it from
   there, so that one run of the suite serves both. A configuration whose `coverage` runs the
   suite itself still works and runs it twice. [The run directory](../configuration.md#the-run-directory)
   has the pair for each stack; `sdlc init` writes it for Go and Python.
3. Run `sdlc gate implementation pass` and `sdlc freeze` as the only command on the line. Put a
   setting the commands need in the configured command in `.sdlc/config.json`, not in front of the
   call.
4. If a script runs the commands after `sdlc gate implementation pass` to the same end, drop that
   run: the gate has made it.
5. A file git tracks and `.gitignore` also matches is in the commit's tree and not in the one
   Gate 5 measured, so the landing then runs the commands every time. Untrack each such file
   that `git ls-files -ci --exclude-standard` lists, or stop ignoring it.

### Verify

```console
$ sdlc doctor
$ sdlc gate implementation pass --note "the work is done"
$ sdlc status --json
```

`doctor` exits 0. The gate prints one line on standard error for each command it runs, naming the
file its output goes to, and records the pass; `status --json` then has a `commands` block with
`current` true. On the next `sdlc freeze` the output says the new tests failed, and `freeze_run`
on the record holds the command and the tree hash. A failing command refuses the gate with
`SDLC-E0095` and names `implementation-run.log`.
